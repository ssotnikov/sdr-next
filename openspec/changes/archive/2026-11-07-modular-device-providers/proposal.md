# Proposal

## Why

Пользователь требует отдельные динамические модули устройств и единую схему взаимодействия с приложением. Сейчас Soapy-адаптер встроен в core и перечисляет три семейства явно; Source SDK не передаёт все аппаратные возможности.

## What Changes

- Добавляется C ABI Device Provider: перечисление устройств, capabilities, конфигурация с фактическими параметрами, IQ, ошибки и завершение.
- HackRF, RTL-SDR и Airspy становятся тремя отдельными DLL/SO, используют общий внутренний Soapy backend без зависимости core от Soapy.
- Manifest-модули загружаются из установленной папки devices при запуске и обновлении списка в остановленном состоянии. Отсутствующий или несовместимый модуль не блокирует остальные и файловый/synthetic RX.
- Существующий Source/Demodulator SDK v1.0 сохраняется совместимым.
- BREAKING: аппаратные ID переходят с soapy: на device:<provider>:<key>, CLI аппаратного benchmark требует явного модуля. Сохранённые ID мигрируются только при однозначном соответствии.
- Реальные RTL-SDR/Airspy испытания остаются отложенными по ADR-016. Изоляция аварий нативного кода не добавляется.

## Capabilities

### New Capabilities

- `device-providers`: независимые подключаемые модули устройств, единый ABI, обнаружение, отсутствие обязательных аппаратных модулей и безопасный lifetime.

### Modified Capabilities

Нет опубликованных основных specs. Текущий change владеет новым контрактом; родительский plan-mvp-v0-1 сохраняет функциональный RX и приёмку, со ссылкой на новый контракт.

## Impact

sdk/include/sdr/device_plugin.h, core loader/source, app Engine, три device plugins, CMake, benchmark, packaging, тесты и документация. Архитектура и контракты фиксируются в docs/sdr/ADR-017-device-provider-modules.md и DEVICE_PLUGIN_API.md. Обязательная аппаратная квалификация остаётся HackRF.
