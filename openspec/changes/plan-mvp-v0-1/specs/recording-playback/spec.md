# Spec Delta

## Purpose

Обеспечить ручную запись демодулированного аудио и IQ и повторяемый файловый источник для практического использования и регрессионных проверок.

## ADDED Requirements

### Requirement: Ручная запись WAV
Приложение SHALL по команде пользователя начинать и завершать запись демодулированного аудио в WAV с валидными заголовками и фактическими параметрами аудио.

#### Scenario: Завершённая WAV-запись
- **WHEN** пользователь записывает контрольный аудиофрагмент и штатно останавливает запись
- **THEN** независимая проверка читает WAV, а его каналы, sample rate, число отсчётов и длительность соответствуют записанному аудио

### Requirement: Документированный Raw IQ
Приложение SHALL записывать Raw IQ и обеспечивать достаточное описание для воспроизведения: тип и порядок отсчётов, byte order, sample rate, центральную частоту и известные разрывы. JSON sidecar остаётся предложением R; точный формат и правила времени требуют утверждения O-008.

#### Scenario: Проверка записи IQ
- **WHEN** завершённая запись открывается с утверждённым описанием формата
- **THEN** файловый источник восстанавливает отсчёты и частотную шкалу; файл не объявляется SigMF без подтверждения его соответствия

### Requirement: Файловый источник
Приложение SHALL воспроизводить IQ-файл с явно определёнными параметрами через тот же приёмный тракт. Отсутствующие обязательные параметры и некорректные данные SHALL давать диагностируемую ошибку вместо неявного угадывания формата.

#### Scenario: Контрольное воспроизведение
- **WHEN** открывается golden IQ с известным форматом
- **THEN** спектр и демодуляция дают повторяемый результат, а конец файла завершает поток без чтения за его пределами

#### Scenario: Неизвестный формат
- **WHEN** для Raw IQ не определены sample rate или тип отсчётов
- **THEN** приложение запрашивает недостающие параметры либо отказывает с их перечнем

### Requirement: Видимые ошибки записи
Приложение SHALL сообщать об ошибке открытия файла, заполнении диска и обнаруженной потере блоков. Запись с ошибкой SHALL не помечаться как полностью успешная; правила incomplete, смены параметров и восстановления требуют O-008.

#### Scenario: Диск переполнен
- **WHEN** во время записи больше невозможно записать очередной блок
- **THEN** пользователь видит ошибку и состояние неполной записи, а приёмный тракт действует по утверждённой политике без бесконечного ожидания диска
