# Spec Delta

## Purpose

Позволить пользователю сохранять локальную конфигурацию приёмника и находить причины ошибок без фоновой передачи диагностических данных.

## ADDED Requirements

### Requirement: Локальная конфигурация JSON
Приложение SHALL сохранять настройки локально в JSON и восстанавливать допустимые параметры при запуске. Схема, миграции и расположение настроек в портативной поставке SHALL быть документированы до реализации хранения.

#### Scenario: Повторный запуск
- **WHEN** пользователь сохраняет допустимые параметры и перезапускает приложение
- **THEN** настройки восстанавливаются; отсутствующее устройство обозначается как недоступное, а не как успешно открытое

#### Scenario: Повреждённый файл настроек
- **WHEN** JSON повреждён или версия схемы не поддерживается
- **THEN** приложение показывает понятную ошибку и предлагает безопасный запуск без разрушения исходной конфигурации

### Requirement: Диагностика приёма
Приложение SHALL показывать активный источник, фактический sample rate, состояния сеанса, известные разрывы IQ, аудио-underrun, заполненность очередей и ошибки записи/плагинов. События SHALL позволять сопоставлять причину со временем и сеансом.

#### Scenario: Перегрузка тракта
- **WHEN** возникает зарегистрированное переполнение IQ или аудио-underrun
- **THEN** соответствующая метрика и структурированное событие доступны пользователю и отчёту испытания

### Requirement: Приватность по умолчанию
Приложение SHALL хранить настройки и диагностику локально и не отправлять телеметрию или crash reports автоматически по умолчанию. Формат ошибок, содержимое crash reports и правила явного экспорта требуют O-020.

#### Scenario: Первый запуск и ошибка
- **WHEN** приложение запускается с настройками по умолчанию и фиксирует ошибку
- **THEN** диагностические данные не отправляются по сети автоматически
