# Протокол длительного Windows RX

Дата: 2026-11-08. Основание: ADR-015 и поручение пользователя начать восемь часов испытаний. Пороги и scope MVP не изменяются.

Режим запускается явно: `sdr_app --endurance-dir <fresh-directory> --endurance-seconds 28800 --endurance-provider device:org.sdr.device.hackrf:`. Требуются подключённый HackRF, совместимый внешний runtime, native Windows GUI и доступный аудиовыход. Профиль: 2.4 MSPS, 100 MHz, WFM, gain 16, PPM 0, Bias-T off, direct sampling off. WAV mono PCM16 48 kHz около 2.8 GB; Raw IQ около 553 GB не записывается. Небольшая громкость не отключает аудиотракт.

Отсчёт начинается после подтверждения RX/audio/WAV. Нормальное завершение останавливает запись и RX, дожидается остановки и сохраняет итоговый JSON. Сырой JSONL сбрасывается на диск каждую секунду; отсутствие summary или ручное закрытие означает незавершённость. Диагностика и пользовательские артефакты остаются локально вне Git. Физические серийные номера не включаются в отчёт.

CPU измеряется по process time / wall time / logical processors. RAM: working set и private bytes; сохраняется максимум обоих показателей. Spectrum FPS — изменившиеся спектры, дошедшие до frameSwapped, а не просто число DSP FFT. Логируется также доставка новых спектров в GUI. Queued ping из отдельного потока раз в 250 ms измеряет задержку GUI event queue; p95 является proxy, не подтверждением реакции на реальный пользовательский ввод. Физическая RF→audio latency требует отдельного контрольного сигнала и остаётся not_verified. Нулевые underrun не доказывают слышимость.

После неуспешного теста окно остаётся открытым с FAILED и причиной; summary уже сохранён. Измерения/probe останавливаются и запрет автоматического сна снимается сразу после завершения теста. Runner отмечает `failed_window_open`, затем ожидает закрытия окна; итог теста хранится отдельно от exit code процесса. Прежние прогоны до этого изменения автоматически закрывали окно при failure.

Во время измерений панели настройки и shortcuts Space/Escape/Ctrl+O отключены, чтобы случайный ввод не менял сеанс; закрытие окна остаётся способом явного прерывания. В обычном режиме shortcuts доступны, autoRepeat для Space/Escape выключен. Автоматический сон/гашение экрана предотвращаются только пока измеряется тест; power plan не меняется. Потеря AC фиксируется как отклонение эталона. Тяжёлые сборки перед основным прогоном завершаются.

Даже завершённый чистый прогон даёт частичный verdict: остаются отдельные измерения UI input и audio latency, Windows 10/Linux, 10/20 MSPS и остальные gates MVP. Запуск теста не является его завершением.

## Проверка сохранения окна при ошибке

2026-11-08: MSVC 2026 сборка и CTest 7/7 pass, включая QML guard controls. Для native GUI намеренно задан отсутствующий provider в `build/endurance/window-preservation-check`. После 15 s startup failure появился `summary.json` со state=failed, процесс остался жив, в окне видны FAILED и причина. Через UI проверены Space/Escape: окно остаётся, RX не запускается. Затем окно закрыто явно, ordinary SDR Next вновь открыт с доступными контролами. Это проверка поведения ошибки, не аппаратный burn-in. Runner дополнительно проверен синтаксическим разбором; его ветка `failed_window_open` не проверялась отдельным полным end-to-end запуском wrapper в этой проверке.
