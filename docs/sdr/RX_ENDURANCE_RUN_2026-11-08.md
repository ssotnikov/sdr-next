## Итог и причина исчезновения окна

В 13:30:55 МСК программа штатно завершила тестовый процесс с exit 2 после ошибки `IQ queue overflow: processing/storage cannot keep up; RX stopped`. Измеряемая длительность — **10250.001 s = 2 ч 50 мин 50 с**, вместо 28800 s. Окно исчезло, поскольку opt-in harness после остановки RX/записи вызывает QCoreApplication::exit(2); это подтверждённое управляемое завершение, не свидетельство падения GUI.

Проверены все 10250 строк JSONL: счётчик IQ монотонен, максимальный интервал между замерами 1.027641 s, интервалов >2 s нет. Первый audio underrun зарегистрирован в 11:13:29 МСК (2006 s), первый audio drop — в 13:22:13 МСК (9730 s). Последний streaming sample предшествует fault, поэтому итоговые overflow/state/error берутся из summary, а не только из последней строки метрик.

WAV: **984100416 bytes**, mono PCM16 48 kHz, длительность **10251.046 s** с учётом начала записи до отсчёта. Независимо проверены RIFF/WAVE/data, channel count/sample rate/bit depth, RIFF/data sizes и фактическая длина файла — корректны. Это подтверждает целостность контейнера, не качество/непрерывность аудио. Локальный `analysis.json` сохраняет агрегаты; raw файлы остаются вне Git.

В acquisition worker переполнение означает неудачную постановку блока в ограниченную IQ очередь после ожидания 20 ms. При block_size 16384 и Fs 2.4 MSPS очередь из 8 блоков содержит около 54.6 ms IQ. Низкий средний CPU не исключает краткие задержки обработки, синхронной записи или планировщика. Текущие метрики не разделяют эти причины; увеличение очереди без измерения latency не обосновано. Нужны отдельная диагностика задержек и повторный полный прогон после исправлений.

После сообщения пользователя об исчезновении окна обычный приёмник вновь запущен без endurance-аргументов; доступное окно в состоянии Idle подтверждено через UI. Сбойный прогон не перезапускался и его результаты не перезаписывались. Родительская задача 7.4 остаётся открытой; успешная восьмичасовая приёмка не заявляется.
