# ADR-019 — Пробуждение RX worker по уведомлению

Дата: 2026-11-08. Статус: принято в рамках технической делегации пользователя. Основание — разбор повторных остановок и воспроизводимый polling механизма ожидания.

## Решение
DSP worker при отсутствии работы ожидает внутренние notifications вместо sleep(1 ms) и повторного опроса. Источники уведомлений — успешная постановка IQ, command post, завершение acquisition (включая ошибку). Generation counter фиксируется перед чтением очередей; изменение revision и notification синхронизированы wake mutex. Stop-aware condition_variable_any завершает ожидание при stop token.

Это внутреннее взаимодействие Engine, не расширение Plugin SDK host callbacks. Hardware USB callbacks не блокируются на данном wake; notification делает acquisition worker после enqueue. Размеры IQ/audio буферов, 20 ms backpressure и политика fail-on-overflow остаются прежними.

Добавляются диагностические maxima FFT/spectrum, audio push и полного блока, а также число переходов в idle wait. Отсутствие ненужных периодических пробуждений проверяется отдельно от аппаратного SLO.

## Предел вывода
Третий прогон зарегистрировал worker gap 405 ms, source read 243 ms, audio push gap 290 ms, при DSP до 14.6 ms и writer до 9.7 ms. Polling — подтверждённый недостаток реализации ожидания; его вклад в конкретную 405 ms паузу не установлен. Замена устраняет зависимость этого ожидания от периодического таймера, но не гарантирует отсутствие вытеснения, DPC, USB stalls и иных системных задержек. Для приёмки нужен новый длительный результат; память >512 MiB и неизмеренная latency остаются открытыми.
