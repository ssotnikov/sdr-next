# SDR Next — дополнительные функции MVP по примеру SDR#

Дата: 2026-11-08. **Статус: предложения для выбора, не согласованное расширение MVP.** Код приложения и обязательные gates этим анализом не меняются.

## Запрос и источники

Запрос пользователя: «Также изучи пример UI SDRSharp и сформулируй список дополнительного функционала для mvp.»

Основание: предоставленные скриншоты SDR# Studio 1.0.0.1922, исходные требования USER_REQUIREMENTS_ORIGINAL.md, текущие core/app/Device Provider API, ADR-014/015/017/020/022. На изображениях видны Radio с Bandwidth/Squelch, аппаратные LNA/VGA/Amp, Display с View/Window/Resolution/сглаживанием, правые Zoom/Contrast/Range/Offset, IF/Audio Spectrum, Frequency Manager и Band Plan, названия дополнительных DSP-модулей. Видимое меню — свидетельство наличия элемента UI, не проверка качества/семантики его DSP.

Справочный первоисточник: [официальная страница Airspy с SDR# и руководствами](https://airspy.com/download/). Прямая ссылка старого guide v3.3 недоступна, Big Book 2024 превышает лимит инструмента чтения; полный PDF и работа SDR# не объявляются изученными. Выводы о показанных элементах основаны на самих скриншотах, выводы о пробелах SDR Next — на локальном коде.

Числа 145.5 MHz, 10 MSPS и FFT 65536 на изображении не становятся новыми параметрами/критериями SDR Next. Структура меню и терминология служат референсом, ресурсы/исходники SDR# не копируются.

## Что уже предусмотрено и не является новой функцией

| Область | Состояние в SDR Next | Что остаётся дополнением |
|---|---|---|
| Start/stop, частота, offset, AM/NFM/WFM | Есть в GUI/engine, проверка полной приёмки отдельно | Поразрядная настройка, шаг, управляемая полоса |

## Рекомендуемый минимальный набор дополнений

Приоритеты — рекомендация автора анализа: High для основной рабочей цепочки, Medium для второй волны, Low для расширения. Это не утверждённые пользователем приоритеты и не календарные оценки.

| ID | Функция | Приоритет | Что добавить | Проверяемый результат/зависимость |
|---|---|---|---|---|
| S-01 | Поразрядная настройка частоты и шаг | High | Колесо/клавиши по выбранному разряду, шаг настройки, ↑/↓, явные единицы | Показаны подтверждённые actual frequency/offset с учётом шага аппаратуры; сохранены пределы source и единый VFO |
| S-02 | Полоса канального фильтра | High | Число/пресеты в Hz для AM/NFM/WFM, выделение полосы и перетаскивание границ | Визуальная полоса соответствует реальному фильтру; ошибки за пределами допустимой полосы отклоняются; действуют DSP-допуски ADR-015 |
| S-03 | Независимые шкалы спектра и waterfall | High | Min/max dBFS, waterfall contrast/gamma отдельно от выбранной карты, сброс | Меняются только отображение и его история, не DSP/AGC/IQ; требуется пересмотр хранения истории из ADR-022 |
| S-04 | Spectrum / Waterfall / Both | High | Три режима и регулируемое соотношение высот вместо фиксированных 36/64% | Скрытие/возврат графика и восстановление настроек не перезапускают RX |
| S-05 | Быстрый mute | High | Доступная кнопка рядом с громкостью, восстановление прежнего уровня | IQ/DSP/запись продолжаются; mute не создаёт ложные underrun и не меняет источник |
| S-06 | Управляемый канальный squelch | High | Enable/bypass, мощность после выделения канала, hysteresis/hold | Сильный внеполосный сигнал сам не открывает squelch; отсутствует дребезг у порога; порог и режим сохранены |
| S-07 | Аппаратные gain stages | High для HackRF | Раздельные LNA/VGA/RF Amp, где их сообщает provider; общий gain — fallback | GUI строится по generic capabilities; именованные стадии/readback требуют согласованного совместимого расширения Device Provider ABI и аппаратных проверок |

Мой рекомендуемый порядок: S-01/S-04/S-05 как малые UX-дополнения; S-02/S-06 как основная работа с каналом; затем S-03 вместе с уточнением истории визуализации; S-07 отдельным этапом для доступного HackRF. Доработки стабильности RX и незавершённая приёмка продолжают иметь приоритет.

## Расширения для обсуждения после минимального MVP

Предлагаю выделить отдельные изменения для LSB/USB/CW/DSB/SAM; IF/baseband/audio Noise Blanker и Noise Reduction; multi-notch и co-channel cancellation; scanner/activity search; CAT/Calico CAT; многоканальных VFO; автоматических/циклических/запускаемых по squelch записей. Для них нужны отдельные DSP/API/UX решения и качественные тесты, а не только элементы меню. Исходные P1-требования сохраняются, перенесение здесь — рекомендация, не согласованное исключение.

Для каждой обработки нужны явный capture point, bypass и измерение CPU/latency. Software AGC, аппаратный AGC, ручной RF gain и audio volume — разные функции. IF/Audio FFT — разные tap, не два экземпляра широкополосного RF-графика.

## Выявленные технические зависимости

1. **Полоса и squelch.** Config сейчас не содержит bandwidth, cutoff жёстко выбран в Demodulator::configure: WFM 85000, NFM 10000, AM 6000 Hz (это cutoff, не полный BW). power_db рассчитывается по входному input до channel FIR; squelch сравнивает именно его. Нужны канал/полоса/метрика и отдельные тесты, не просто новый control.
2. **Шкала waterfall.** ADR-022 планирует нормализованные 8-bit levels. После clipping к старому диапазону расширение min/max не восстанавливает пропавшую информацию. При выборе S-03 следует сначала обновить ADR: хранить исходный dB либо достаточно широкий фиксированный диапазон абсолютных квантованных уровней с validity. Выбор точности/формата и benchmark ещё не принят; автоматически менять уже выбранный контракт не следует.
3. **FFT.** sdr::spectrum допускает степень двойки и Hann, но Engine/Controller/SpectrumItem используют текущие 2048 bins; SpectrumItem отклоняет другой размер. Новый selector требует полного согласованного пути, координат оси и численных тестов, не только вызова core API.
4. **Аппаратура.** device_plugin.h ABI 1.0 и Config имеют один gain. Soapy backend читает список gains и использует общий setGain/getGain. Названия/диапазоны/шаг/actual stage должны приходить из каждого динамического provider; основной GUI не получает hardcoded HackRF-ветку. RF Amp не подменяется Bias-T. Старые модули и отсутствие конкретной capability должны сохранять работу.
5. **Время и диагностика.** Текущий frame передаёт bins без временной оси. Истинные метки/SNR/уровни канала требуют отдельных метаданных/оценки. Диагностические FFT и marker frames идут по bounded latest-only visual path, не блокируют device/DSP.
6. **Запись и reconfigure.** Смена DSP-параметров при записи уже ограничена ADR-014. Новые bandwidth/AGC/IQ controls обязаны соблюдать эту политику; mute/display controls не меняют capture data. В endurance сохраняются действующие guards.

## Ориентиры проверки рекомендуемого набора

Это не новая утверждённая численная приёмка, а основания для будущих сценариев:
- Поразрядное изменение частоты: показываются source actual frequency/offset, включая аппаратное округление; неверный ввод не сбрасывает работающий сеанс.
- Полоса: на synthetic IQ проходят нужный тон и подавляется контрольный внеполосный; применяются уже согласованные допуски ADR-015 для поддержанного режима.
- Squelch: при слабом канальном сигнале и сильном сигнале вне него gate не открывается ошибочно; hold/hysteresis требуют отдельного выбора значений/тестового профиля.
- Display: одинаковый IQ frame даёт одинаковые численные bins и WAV до/после визуальной настройки; карта и диапазон не меняют масштаб измерения самих данных.
- Mute: слышимость выключена и восстановлена, потоки/запись и качество счётчиков не прерываются.
- Gain stages: неподдерживаемые регуляторы не показываются активными; после ошибки устройства предыдущие/actual параметры не выдаются за успешно применённые.
- Любая новая функция проверяется с прежними CPU/RAM/FPS/UI/audio latency критериями; повышенные FFT/дополнительные окна не отменяют обязательный baseline.
