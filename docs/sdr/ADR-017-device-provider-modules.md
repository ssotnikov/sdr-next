# ADR-017 — Отдельные динамические модули устройств

Дата: 2026-11-07. Статус: **принято по требованию пользователя**: каждое устройство — подключаемый модуль, отсутствие модулей не мешает программе, взаимодействие единообразно. Детали C ABI выбраны в рамках технической делегации.

## Решение

Для аппаратных семейств вводится Device Provider ABI v1.0. HackRF, RTL-SDR и Airspy поставляются отдельными DLL/SO с manifest, независимо устанавливаются в devices рядом с приложением. Один provider перечисляет физические экземпляры своего семейства. Хост не содержит имён семейств или Soapy-кода. Добавление нового совместимого provider не требует пересборки хоста.

Единый интерфейс включает enumerate с descriptor/capabilities, create с requested/actual config, read IQ, destroy и last_error. Host владеет входными/выходными POD-буферами, module — opaque instance. Version/struct_size/ограничения массивов проверяются. Native библиотека удерживается живым instance. Read/start/close выполняются в acquisition worker. Повторная конфигурация — stop/recreate, registry обновляется только без RX.

Общая приватная реализация Soapy может переиспользоваться тремя модулями, но не является частью core. Soapy SDK требуется только для сборки этих optional модулей; их runtime/драйверы устанавливаются отдельно. Файловый и synthetic источники встроены и доступны без аппаратных модулей. Существующий Source/Demodulator ABI v1.0 сохраняется; его ограничения из ADR-016 относятся к прежнему контракту IQ-расширений, не новому Device Provider.

Автозагрузка распространяется на manifests установленной доверенной папки devices, а не на произвольные DLL в cwd/PATH. Некорректный или отсутствующий модуль/зависимость фиксируется локально и не блокирует другие. Crash isolation остаётся после MVP. Реальные RTL-SDR/Airspy испытания по ADR-016 остаются отложенными.

## Следствия

Убираются whitelist семейств и Soapy dependency из core. Упаковщик копирует отдельную папку devices. Меняется аппаратный ID и CLI benchmark; старый ID мигрируется только при однозначном совпадении. Новая реализация уточняет аппаратный путь ADR-014 и устраняет описанное ограничение ADR-016. OpenSpec-владелец нового контракта: modular-device-providers; родительский MVP по-прежнему владеет DSP/GUI/длительной и платформенной приёмкой.
