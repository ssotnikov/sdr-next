# MVP v0.1 — план реализации

Дата плана: 2026-11-06. Реализация начата 2026-11-07. Текущие решения, делегация и критерии пользователя описаны в ADR-013/ADR-014/ADR-015; исходные таблицы ниже сохраняют историю планирования. Чек-лист OpenSpec отражает только полностью проверенные задачи. Фактические свидетельства и оставшиеся gates — в [отчёте](MVP_V0_1_VERIFICATION.md).

- [Подтверждение пользователя](ADR_USER_CONFIRMATION_ORIGINAL.md) и [ADR](ADR_REGISTER.md) — 12 принятых решений.
- [Открытые вопросы](OPEN_DECISIONS.md) — O-001…O-020; этот план не меняет их статус.
- [OpenSpec proposal](../../openspec/changes/plan-mvp-v0-1/proposal.md), [спецификации](../../openspec/changes/plan-mvp-v0-1/specs/), [задачи](../../openspec/changes/plan-mvp-v0-1/tasks.md).

OpenSpec хранит спецификации поведения и задачи; архитектурные решения и их обоснования — в `docs/sdr/`. Любое закрытие O-ID требует явного подтверждения пользователя и ссылки на принятое решение. Измерение либо создание прототипа само по себе не означает согласование. Производственные задачи, зависящие от O-ID, выполняются после решения; исследовательский PoC допустим с явным статусом эксперимента.

## Предлагаемый состав

Уточнение 2026-11-07 по [ADR-016](ADR-016-deferred-device-qualification.md): реальные испытания RTL-SDR/Airspy перенесены после MVP. Ниже перечисление адаптеров не означает их подтверждённой аппаратной поддержки. Для v0.1 обязательна применимая аппаратная приёмка HackRF; отложенные модели экспериментальны и не блокируют выпуск своим отсутствием.

Windows 10/11 и Ubuntu/Debian x86-64; один активный SDR; RTL-SDR, HackRF One, Airspy и файл IQ; AM/NFM/WFM; аудиоустройство по выбору; спектр FFT и waterfall; собственный ограниченный docking; SDK Source + Demodulator для C++/Rust; ручная WAV/Raw IQ запись; JSON-настройки; локальная диагностика; портативная поставка.

**Не превращать в согласованные ограничения:** один демодулируемый VFO в v0.1 — предложение R baseline; конкретный sidecar JSON — R; точный состав docking — O-007. Формат IQ, ABI, библиотеки, rendering fallback и пороги производительности остаются открытыми. Дополнительное ограничение числа VFO нужно согласовать перед фиксацией маршрутизации G1/G2.

После MVP: TX, Android/ARM64, SoapyRemote, изолированный plugin host/sandbox, каталог плагинов, специализированные декодеры, GPU DSP, расширенные записи и средства анализа. Перенос функции за MVP не означает отказ от исходного требования. Для пунктов, чей статус A/D и R в baseline неоднозначен, до реализации уточняется релизный объём; приоритет имеют прямые решения пользователя.

## Архитектурные границы

Сохранить принятые ADR-001…ADR-012. Базовая форма — независимое C++20-ядро и Qt Quick/QML-представление. Предлагаемое разбиение из baseline: base, radio, hardware adapters, dsp, audio/recording, plugin runtime, application, gui. Оно ещё не является готовым публичным набором заголовков.

Направление зависимостей: `gui -> application -> radio/dsp/recording/plugin-runtime -> base`; аппаратные адаптеры реализуют интерфейсы radio, плагины зависят от SDK. DSP публично не зависит от Qt. UI получает состояния и подготовленные спектральные кадры. Приёмник не ждёт отрисовку; дисковая и визуальная ветви не создают неограниченной очереди.

Предлагаемый поток: `source -> нормализация -> транспорт IQ -> DDC/filter/decimation -> demodulator -> audio`; отводы на FFT и IQ writer, аудиоотвод на WAV writer. Точки записи, принадлежность DDC/ресемплинга и формат блоков утверждаются до реализации соответствующих контрактов. Фан-аут требует независимых очередей и определённого времени жизни общих блоков.

## План этапов

Даты и трудозатраты пока не оцениваются: неизвестны доступность железа и ОС, команда и итоги PoC. Ни один этап не считается завершённым только из-за наличия кода.

| Gate | Содержание | Зависимости | Свидетельство завершения |
|---|---|---|---|
| G0 Foundation | CMake/vcpkg, версии, слои, headless tests, CI и политика зависимостей | O-001; подтверждённая базовая среда | Чистая сборка и тесты ядра Windows/Linux без Qt; GUI shell собирается отдельно |
| G1 RX PoC | Синтетический/file источник для проверки транспорта, затем HackRF; метрики; FFT/waterfall PoC | G0; O-002/003, начальная O-006; решение о VFO | Живой IQ → FFT → окно на обеих ОС; start/stop, ошибки и разрывы измеримы; RTL-SDR/Airspy реальные испытания после MVP |
| G2 DSP/Audio | Контрольные IQ-наборы, AM/NFM/WFM, аудиовыход и reconfigure | G1; O-004/005; DSP-допуски из O-012 | Контрольные сигналы демодулируются, проверены аудиоустройства и смена rate; выбранные допуски подтверждены |
| G3 GUI | QML shell, tuning, визуализация, ограниченный docking, темы, конфигурационный UX | G1/G2; O-007/013/015, графическая часть O-014 и формат ошибок O-020 | Основные действия работают во время RX; раскладка восстанавливается; ошибки видимы; проверен утверждённый набор графических сред |
| G4 SDK | Публичный header, manifest, загрузка/отключение, C++ SDK, Rust bindings, два отдельных примера | G1/G2; O-009/010 и формат O-003 | Примеры Source/Demodulator работают Windows/Linux; тесты версий, памяти, teardown и FFI проходят |
| G5 Recording/Config | WAV, Raw IQ, metadata, JSON-конфигурация, диагностические события | G2/G3; O-008, необходимая часть O-020 | Файлы проверены независимым чтением и файловым RX; ошибки диска/конфига воспроизводятся |
| G6 Release preparation | Применимая матрица HackRF, burn-in, performance, портативные пакеты, документация, лицензии | G0–G5; O-006/011/012/014/019/020 с уточнением ADR-016 | Подготовлены свидетельства по F-001…F-014; RTL-SDR/Airspy реальные испытания deferred; пройдены проверки G6 и аудит лицензий |
| G7 Clean Windows acceptance | Финальный портативный пакет на чистых Windows 10 22H2 x64 и Windows 11 x64 | Завершена разработка MVP и подготовлен релизный кандидат в G6 | На обеих ОС пройдена [задача 8.1](../../openspec/changes/plan-mvp-v0-1/tasks.md#8-g7--финальная-проверка-на-чистых-windows); результаты учтены перед выпуском |

Критическая последовательность: `G0 -> G1 -> G2 -> {G3, G4} -> G5 -> G6 -> G7`. Запись может разрабатываться после готовности аудио и формата, не ожидая всего SDK, но итоговый G6 требует обе ветви. Ранний FFT/waterfall PoC в G1 предшествует полноценному GUI в G3. Контракт сохраняет путь Soapy для Airspy, но его реальные испытания перенесены после MVP по ADR-016; они не входят в текущий G6.

Здесь параллельность означает независимость инженерных работ, а не поручение запускать дополнительных агентов. На каждом этапе ведутся тесты, документация и учёт лицензий. После каждого gate фиксируются результат, версии, ссылки на тесты, известные ограничения и решение о переходе дальше.

## Протокол испытаний

Для каждого результата сохранять: commit/build (когда появится Git), ОС, инструменты/библиотеки, устройство/firmware/driver, USB, питание, CPU/RAM/iGPU, target/actual sample rate, IQ-формат, FFT, демодулятор, запись, длительность, raw metrics/logs и вывод. До появления Git использовать однозначный идентификатор сборки и контрольные суммы.

Статусы: `pass` — проверка выполнена и критерий соблюдён; `fail` — выполнена и нарушен; `blocked` — нет согласования, среды или железа; `not-applicable` — есть явное обоснование неприменимости к конкретной комбинации. Неприменимая скорость устройства не отменяет требование проверить профиль на другом применимом источнике. Отсутствие железа — blocked, а не pass или not-applicable.

Функциональные тесты: DSP golden/synthetic, lifecycle RX, capability settings, EOF/неверный файл, исчезновение USB и аудиоустройства, disk full, major mismatch, unload при активном вызове, повреждённый JSON. Файл и синтетический источник позволяют запускать CI без USB; такие тесты не заменяют аппаратную матрицу.

Производительность: 2.4/10/20 MSPS, разные режимы демодуляции и записи, замедленный GUI/диск, длительная работа и start/stop. До O-011/O-012 это исследовательские измерения. Не вводить произвольные 60 FPS, 8/24 часа или пороги CPU как утверждённые SLO.

## Условия завершения v0.1

Все обязательные сценарии и F-ID подтверждены; необходимое для них согласование завершено; поддерживаемое железо/ОС описаны; долгие испытания и метрики выполнены по утверждённому протоколу; лицензии фактических бинарников проверены; пользовательская инструкция, Developer Guide, DSP API и SDK-примеры готовы. При нехватке свидетельств возможна только явно предварительная сборка без заявления о полной приёмке.

Пункты O-016…O-018 остаются открытыми после MVP. Их наличие не блокирует desktop-релиз, пока v0.1 не начинает включать соответствующие функции. Остальные открытые вопросы блокируют те проверки, которые от них зависят. Изменение OpenSpec архивируется после реализации и проверки, а не после создания этого плана.
