# ADR-013 — Desktop matrix (O-001)

Дата: 2026-11-07. Статус: **принято пользователем** в ответе на вопрос O-001. Матрица Windows уточнена пользователем 2026-11-11.

## Решение

Qt 6.10.0, C++20, x86-64. Windows 10 22H2 и Windows 11 с **MSVC Build Tools из Visual Studio 2026** (v145, 14.50 или новее из семейства VS 2026); Ubuntu 22.04/GCC 11, Ubuntu 24.04/GCC 13, Debian 12/GCC 12. Linux-пакет для общей совместимости собирается с Qt из исходников на Ubuntu 22.04. Наличие платформы в целевой матрице не является свидетельством прохождения испытаний.

| Среда | Статус проверки при начале реализации |
|---|---|
| Windows 11, Qt 6.10.0 | SDK загружен; метаданные VS 2026 присутствуют, но рабочего cl.exe и MSVC x64 libraries нет; MSVC 2022 не найден. Дополнительная проверка — MinGW 13.1 |
| Ubuntu 22.04, GCC 11.4.0 | Локальная WSL-среда доступна, Qt 6.10.0 не установлен |
| Windows 10 22H2 | Отдельная среда для приёмки не предоставлена |
| Ubuntu 24.04 / Debian 12 | Отдельные среды ещё не проверены |

Установка Build Tools была отклонена автоматической проверкой исполнения (`blocked by policy`); проверка с MinGW является дополнительной, не заменяет согласованный MSVC 2022.

## Повторная проверка 2026-11-07

Предыдущий вывод об отсутствии рабочего MSVC больше не актуален. Повторная проверка обнаружила отдельную полную установку **Visual Studio Build Tools 2022 17.14.40**: toolset v143 в каталоге 14.44.35207, cl/link, C++ headers и x64 CRT libraries; компилятор определён CMake как **MSVC 19.44.35228.0**, Windows SDK **10.0.22621.0**. С Qt 6.10.0 msvc2022_64 успешно собраны приложение, SDK examples и тесты; CTest **4/4**. Дополнительно пройден короткий физический HackRF QML/audio test и запуск упакованного GUI без developer PATH. После сборки визуально проверены окно, synthetic RX, spectrum/waterfall и stop; приложение оставлено в Ready.

Никакая установка в ходе этой повторной проверки не выполнялась. У отдельной IDE Visual Studio Professional 2026 найдены cl/link 14.51.36231, но не обнаружены include/vector и lib/x64/libcmt.lib в её toolset. Для проекта использован уже имеющийся MSVC 2022; согласованная матрица не изменена. Windows 10 и оставшиеся Linux/HiDPI/backend gates этим результатом не закрываются.

## Дополнительная пересборка MSVC 2026

Позднее 2026-11-07 пользователь завершил обновление инструментов и запросил новую пересборку. Visual Studio Professional 2026 **18.11.12328.437** теперь отмечена установщиком как complete/launchable; заголовки и библиотеки присутствуют. Проект полностью собран в отдельном `build/windows-msvc2026`: **MSVC 19.51.36260.0**, toolset **14.51.36231**, Windows SDK **10.0.26100.0**, C++20, Ninja, Release. Qt сохранён **6.10.0 msvc2022_64**. CTest **4/4** с `SDR_TEST_HACKRF=1`. Это дополнительное свидетельство по запросу пользователя; общая целевая матрица и непрошедшие gates не переутверждаются результатом одной сборки.

Основание: пользователь явно согласовал предложенную матрицу. Более ранние варианты O-001 остаются в оригинальной baseline как исторический материал.

## Переход на MSVC 2026 (2026-11-11)

Пользователь заменил MSVC 2022 на MSVC 2026. Для приложения и примеров SDK используются инструменты x64 Visual Studio/Build Tools 2026, а для Rust — `x86_64-pc-windows-msvc`. Готовый Qt SDK 6.10.0 сохраняет имя `msvc2022_64` и линкуется более новым MSVC. Совместимость целевых Windows и установка runtime проверяются на финальном пакете в задаче 8.1. [Правила бинарной совместимости Microsoft](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017?view=msvc-180)

## Источники

[Qt 6.10 Supported Platforms](https://doc.qt.io/qt-6.10/supported-platforms.html) перечисляет Windows 10/11, Ubuntu 22.04/24.04, Debian 12 и соответствующие семейства компиляторов. Готовые Linux-бинарники Qt собраны на Ubuntu 24.04; для более старой glibc необходима сборка из исходников. Точные локальные версии проверяются сборкой; документ не объявляет протестированной всю матрицу.
