# ADR-016 — Перенос реальных испытаний RTL-SDR и Airspy

Дата: 2026-11-07. Статус: **принято пользователем**: «Реальные испытания RTL-SDR и Airspy откладываем на будущее».

## Решение

Реальные испытания RTL-SDR и Airspy перенесены за MVP v0.1. Их отсутствие больше не блокирует выпуск v0.1 само по себе. Существующий код подключения через SoapySDR сохраняется; эти семейства имеют статус **экспериментально, на реальном устройстве не проверено**. Перенос не является успешной приёмкой или подтверждением совместимости.

Для аппаратной приёмки v0.1 остаётся HackRF One: обязательные применимые настройки, ошибки, unplug/reopen, ОС и длительный профиль должны иметь собственные результаты. Файловый и синтетический источники сохраняются. O-006 для полной будущей матрицы RTL-SDR/HackRF/Airspy остаётся открытым; незавершённая часть по RTL-SDR/Airspy относится к последующему этапу. Остальные gates MVP не отменены.

Исходная baseline и реестр 12 первоначальных ADR остаются неизменными. Текущие OpenSpec proposal/design/specs/tasks и отчёт используют это явное уточнение области приёмки. Задачи реальных RTL-SDR/Airspy испытаний переносятся в roadmap, не отмечаются выполненными.

## Уточнение текущей модульности — факт реализации

Историческое состояние до ADR-017. Встроенный аппаратный путь ниже заменён независимыми Device Provider модулями; перенос реальных испытаний остаётся в силе.

- SoapyRTLSDR, SoapyHackRF и SoapyAirspy — внешние подключаемые драйверы SoapySDR. В приложение их реализации не встроены; используется общий адаптер через динамически загружаемый C API SoapySDR.
- Сам адаптер SoapySDR сейчас скомпилирован в core. В `core/src/source.cpp` поиск ограничен явным списком `hackrf`, `rtlsdr`, `airspy`. Поэтому установку любого другого Soapy-модуля нельзя считать достаточной для появления нового семейства в GUI.
- Собственный SDK Source поддерживает загрузку DLL/SO по manifest. Но ABI v1.0 передаёт rate/center/offset и IQ, не содержит перечисления устройств и полного capability/control API для gain/PPM/Bias-T/direct sampling. В GUI внешний Source регистрируется как один источник с ограниченными аппаратными настройками.

Этот ADR не объявляет реализацию полностью независимым от семейств plugin host и не согласует автоматически расширение ABI или изменение поиска источников. Он фиксирует фактические границы и перенос испытаний. Термины — в [глоссарии](GLOSSARY.md).
