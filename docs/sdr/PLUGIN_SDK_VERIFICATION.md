# Проверка Plugin SDK v0.1

Дата: 2026-11-11. OpenSpec `plan-mvp-v0-1`, задачи 5.5–5.7. Инструкции сборки и установки в [Plugin SDK Guide](PLUGIN_SDK.md).

| Проверка | Windows 11 x64, MSVC 19.51.36260.0 | Ubuntu 22.04.5 x86-64 под WSL, GCC 11.4.0 |
|---|---|---|
| Отдельные сборки C++ Source и Demodulator из копий исходников и публичного `plugin.h` | Две DLL и два manifest | Две SO и два manifest |
| Контроль импортов через `dumpbin /dependents` и `readelf -d` | CRT и системные библиотеки | `libstdc++.so.6` и `libm.so.6` |
| C++ хост с отдельно собранными плагинами | Source выдаёт IQ тона 1 кГц, Demodulator восстанавливает модуляцию 1 кГц с корреляцией >0,95 | Pass |
| Rust 1.89.0, сборка Release и `cargo test --offline --locked` | `x86_64-pc-windows-msvc`, 1/1 | `x86_64-unknown-linux-gnu`, 1/1 |
| Вызов Rust из C++ | IQ тона 1 кГц, отклонение конфигурации, удержание модуля до destroy | Pass |
| Загрузка двух manifest, RX, аудиобуфер, проверка несовместимого ABI и ошибки init, отключение и повторная загрузка | Pass | Pass |
| Полный CTest проекта с Qt 6.10.0 | 8/8 | 7/7 |

`sdr_core_tests` вызывает публичный ABI и проверяет результат обработки AM-модулированного IQ, а `sdr_engine_tests` проверяет путь от регистрации manifest до доставки аудиокадров. При попытке отключить оба работающих модуля хост возвращает ошибку и продолжает RX. После остановки оба модуля отключаются и повторно регистрируются. Библиотека с ABI major 99 отклонена при совместимом manifest, поэтому проверена именно версия, возвращённая библиотекой.

Для проверки Rust panic отдельная копия crate в каталоге сборки была изменена только в ветке `configure` для `sample_rate < 48000`. В этой ветке вместо возврата ошибки вызван `panic!`. На обеих платформах Rust записал сообщение о panic, обёртка `catch_unwind` вернула ошибку через C ABI, а хост успешно создал и вызвал следующий экземпляр и завершил тест с кодом 0. Изменённая библиотека использовалась только для проверки. Контролируемая ошибка C++ Demodulator проверена при недопустимом смещении.

Локальные журналы Windows находятся в `build/sdk-check-20261111/` (`final-ctest.log`, `final-core.log`, `final-engine.log`, `ffi-panic.log`). Путь к журналам Ubuntu (`verification.log`, `final-verification.log`, `ffi-panic.log`) записан в `build/sdk-check-wsl-path.txt`.

Аудио проверено по отсчётам и буферу приложения. Приёмка нативных Linux-дистрибутивов, физического аудиовыхода и чистых Windows отслеживается в соответствующих задачах MVP.
