# ADR-022 — Независимые профили оформления и color maps

Дата: 2026-11-08. Статус: требование пользователя принято; техническая модель выбрана в рамках делегации. **Реализация запланирована, в текущей сборке не заявляется.** Дополняет ADR-020/ADR-021.

## Решение
Разделить четыре ресурса: ui-theme, spectrum-style, waterfall-style, color-map. Режим dark/light/system задаётся отдельно. UI, спектр и waterfall имеют свои dark/light варианты; карта интенсивности не привязана к ним. Пользователь может иметь светлый UI и тёмный спектр/waterfall либо разные фоны двух графиков.

Оформление — ограниченные JSON-данные, не QML/JS/DLL. Встроенные профили остаются неизменяемыми, пользовательские импортируются и экспортируются. Сохраняются стабильные namespaced ID; отсутствующий ресурс вызывает fallback только своего слоя с явным уведомлением. Пользователь отдельно выбрал Classic Teal по своему скриншоту: профиль включается в план каталога. Остальной каталог дополнительных пресетов и совместимость с файлами SDR++ не согласованы; скриншоты задают пример UX, не обязательство копирования.

Цвета интерфейса, фоны/линии/сетка/подписи спектра, фон/noData/сетка/подписи waterfall и карта интенсивности разрешаются отдельно. BrandTheme остаётся поставщиком типографики и метрик; фирменные встроенные цвета — исходные defaults. Надпись SDR Next сохраняет две части и следует ink/dialInk выбранной UI theme, не цветам графиков.

Палитра применяется к сохранённой истории уровней, а не к единственному RGB-буферу. Смена карты должна перекрашивать историю без очистки, device reconfigure или RX restart. Изменения цветов не меняют FFT, шкалу dB, нормализацию, записи IQ/аудио и численные критерии.

## Альтернативы и последствия
Единая тема для всего окна не позволяет независимо настроить waterfall; сохранение только RGB требует уничтожать историю при смене карты. Нативный plugin API для палитр избыточен. Выбраны четыре независимых ресурса и единый resolver immutable snapshot на GUI thread. Разбор JSON и подготовка LUT не входят в DSP/device callback.

Потребуются реестр ресурсов, загрузчик/валидация, миграция настроек, независимые binding и изменение хранения визуальной истории. Дополнительная память и стоимость перекрашивания проверяются benchmark; прежние performance gates не ослабляются. Это не разрешение считать приёмку завершённой.
